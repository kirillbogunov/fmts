# FMTS v0.7.0 — ServiceDesk Phase 1

## Исправления

- Исправлен `Internal Server Error` на дашборде: данные статусов больше не передаются в JSON как SQLAlchemy Row; для интерактивной диаграммы формируется обычный сериализуемый массив.
- Исправлен подсчёт завершённых заявок на дашборде: учитываются статусы `resolved` и `closed`.

## Группы исполнителей

- Добавлен справочник групп/команд исполнителей.
- В группу можно включать сотрудников как исполнителей или наблюдателей.
- Заявку можно назначить на группу.
- При назначении группы FMTS автоматически выбирает наименее загруженного активного техника из исполнителей группы.
- Участники группы-наблюдатели автоматически получают доступ к заявке как наблюдатели.

## Участники заявки

- Разделены `Создатель` и `Заявитель`: диспетчер/руководитель/администратор может зарегистрировать обращение от имени другого сотрудника, при этом сохраняется тот, кто фактически создал запись.
- Добавлены наблюдатели заявки с серверным контролем доступа и уведомлением при добавлении.
- В карточке заявки появился отдельный блок участников: заявитель, создатель, группа, исполнитель и наблюдатели.

## Массовые действия

- В списке заявок для диспетчера, руководителя и администратора добавлен выбор нескольких заявок.
- Массово можно: назначить техника, назначить группу, изменить приоритет, безопасно изменить рабочий статус, создать копии заявок.
- Финальные статусы не выставляются массово, чтобы не обходить обязательный комментарий мастера и учёт времени.

## Шаблоны и наряды

- Добавлен раздел `Шаблоны / наряды`.
- Шаблон хранит заголовок, описание, категорию, приоритет, сервис и группу.
- К шаблону добавляется комплект подзадач.
- При запуске шаблона создаётся главная заявка и дочерние наряды со связями `parent/child`.
- Для группы автоматически выбираются исполнители с учётом текущей загрузки.

## Навигация

Меню разделено по тематике:

- Работа
- ТОиР и активы
- Service Desk
- Аналитика
- Управление

Это сокращает длинную «простыню» меню и делает новые модули понятнее по назначению.

## База данных

Миграция добавочная. Для существующей базы автоматически добавляются `tickets.creator_id`, `tickets.group_id`, `tickets.template_id`, а также таблицы групп, участников, наблюдателей и шаблонов. Старые заявки получают `creator_id = requester_id`, если заявитель уже был указан.

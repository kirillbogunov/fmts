# Что использовать из уже сделанной 1С и что добавить

## Уже существующее — НЕ дублируем

Приложение v0.2 рассчитано на текущий документ **`ЗаявкаХозОтдела`** и его реквизиты:

- `Заявитель`
- `Подразделение`
- `Кабинет`
- `Телефон`
- `Категория`
- `Приоритет`
- `Описание`
- `Мастер`
- `Статус`
- `ДатаВыполнения`
- `КомментарийМастера`

Используются существующие перечисления:

- `Статусы`: `Новая`, `Назначена`, `ВРаботе`, `ОжиданиеМатериалов`, `Выполнена`, `Закрыта`, `Отменена`;
- `Приоритет`: `Низкий`, `Обычный`, `Высокий`, `Срочный`;
- `Категория`: `Электрика`, `Сантехника`, `Мебель`, `Отделка`, `Кондиционер`, `Окна`, `Двери`, `Компьютер`, `Другое`.

`Мастер` оставляем строкой, как в текущей базе. В веб-приложении исполнитель уже является пользователем; при обмене его ФИО записывается в строковый `Мастер`.

## Минимум, который надо добавить сейчас

### 1. Реквизит `WebID` в `ЗаявкаХозОтдела`

Тип: **Строка 36** (можно 50). Это технический идентификатор веб-заявки. Он нужен, чтобы двусторонняя синхронизация была идемпотентной: когда веб создаёт документ 1С и `ПослеЗаписи` сразу отправляет его обратно, приложение узнаёт исходную заявку и не создаёт дубль. Пользователю на форме этот реквизит можно не показывать.

### 2. HTTP-сервис `TOIR`

Корень: `toir`, версия `v1`.

URL-шаблоны:

| Шаблон | Метод | Обработчик |
|---|---|---|
| `sites` | GET | `SitesGET` |
| `tickets` | GET | `TicketsGET` |
| `tickets` | POST | `TicketsPOST` |
| `equipment` | GET | `EquipmentGET` (сначала безопасная пустая заглушка) |
| `inventory` | GET | `InventoryGET` (сначала безопасная пустая заглушка) |

Код обработчиков — `HTTPService_TOIR_Core_Module.bsl`.

### 3. Общий модуль `TOIRWebAPI`

Свойства: серверный, экспортный. Код — `TOIRWebAPI_CommonModule.bsl`.

В модуле объекта `ЗаявкаХозОтдела` заменить старый вызов `GoogleSheetsAPI.ОтправитьЗаявку(...)` на код из `Document_ZayavkaHozOtdela_ObjectModule.bsl`.

## Что добавить для полного ТОиР (следующий слой)

Это уже не нужно для обмена заявками, но нужно для функциональности уровня Okdesk ТОиР.

### Справочник `ОборудованиеХозОтдела`

Рекомендуемые реквизиты:

- `Подразделение` — ссылка на `Подразделения`;
- `ИнвентарныйНомер` — строка 50;
- `КатегорияОборудования` — строка/справочник;
- `Модель` — строка 100;
- `СерийныйНомер` — строка 100;
- `Статус` — перечисление (`Работает`, `Неисправно`, `Ремонт`, `Списано`);
- `ДатаУстановки` — дата;
- `ГарантияДо` — дата.

В `ЗаявкаХозОтдела` добавить реквизит `Оборудование` типа `СправочникСсылка.ОборудованиеХозОтдела`.

### Регистр сведений `ПланыТОИР`

- измерение `Оборудование`;
- ресурсы/реквизиты `ВидТО`, `ПериодичностьДней`, `СледующаяДата`, `Ответственный`, `Активен`, `ЧекЛист`.

### Затраты по заявке

В `ЗаявкаХозОтдела` добавить:

- `СтоимостьРабот` — число 15.2;
- `СтоимостьМатериалов` — число 15.2;
- табличную часть `Материалы`: `Номенклатура`, `Количество`, `Цена`, `Сумма`.

Номенклатуру **не дублировать**: использовать существующий `Справочник.Номенклатура`.

### Остатки склада

Для реальных остатков ЗИП нужен **точный существующий регистр остатков вашей конфигурации**. Его имя из прежней схемы не известно. Пока веб-приложение ведёт собственный склад. Чтобы списание физически делало движения в 1С, нужно сообщить имя регистра/документа склада либо выгрузить структуру метаданных. После этого маршрут `/hs/toir/v1/inventory` можно привязать к нему без создания второго склада.

## Необязательное, но полезное

В `ЗаявкаХозОтдела` можно добавить `WebURL` (строка 250), чтобы из 1С одной кнопкой открывать соответствующую карточку в ТОиР.

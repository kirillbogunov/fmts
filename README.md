# FMTS v0.3.2 — Facility Management & Task System

## v0.4.0 — Mobile / Technician UX

Версия 0.4.0 ориентирована на ежедневную работу мастера со смартфона. В карточке заявки появился блок объекта и кнопка **«Маршрут до объекта»** с выбором Яндекс Карт, Google Maps или 2GIS. Основные таблицы на мобильном превращаются в карточки, добавлена нижняя навигация и увеличены элементы управления. Для работы маршрута достаточно заполнить поле **Адрес** у объекта.


**FMTS — Facility Management & Task System** — самостоятельная система задач и мониторинга работы хозяйственного отдела, ServiceDesk и ТОиР. **Для работы 1С не требуется.**
1С сохранена как отдельный дополнительный коннектор на будущее.

## Что работает самостоятельно

- заявки, статусы, приоритеты и SLA;
- объекты / магазины / площадки;
- цифровые паспорта оборудования и QR-коды;
- история ремонтов и затрат;
- пользователи, роли и исполнители;
- ТО / ППР и автоматическое создание плановых заявок;
- чек-листы ППР;
- склад / ЗИП, остатки и списание в заявку;
- подрядчики;
- вложения и комментарии;
- дашборд;
- локальные категории, статусы, приоритеты, SLA и цвета подсветки;
- REST API / Swagger (`/docs`);
- PWA для установки на Android/iPhone;
- SQLite для быстрого старта;
- PostgreSQL для рабочего Docker-развёртывания.

## Главное изменение v0.3

Источником данных является **сама база ТОиР**. Раздел `Настройки` позволяет администратору
менять названия, цвета и порядок статусов, приоритетов и статусов оборудования, SLA приоритетов,
а также добавлять собственные категории работ.

1С больше не управляет этими значениями и не нужна для запуска. Если интеграция понадобится,
она включается отдельно через `ONEC_ENABLED=true`.

## Быстрый запуск на Windows — чистая система

1. Распакуйте архив.
2. Запустите `run_windows.bat`.
3. Откройте `http://127.0.0.1:8000`.
4. Вход по умолчанию: `admin` / `ChangeMe123!`.
5. Сразу измените пароль в `Профиль`.

При первом запуске создаются только администратор и системные справочные значения. Объекты,
оборудование и пользователи добавляются через интерфейс.

> Для локального HTTP в `.env` должно быть `COOKIE_HTTPS_ONLY=false`.
> После публикации через HTTPS установите `COOKIE_HTTPS_ONLY=true` и правильный `BASE_URL`.

## Демо-режим

Для презентации с готовыми примерами запустите:

```text
run_demo_windows.bat
```

Он создаст тестовые объекты, оборудование, ППР, ЗИП, подрядчика и пример заявки.
Демо-данные добавляются только если соответствующие таблицы пусты.

## Docker + PostgreSQL

Для рабочего сервера:

1. Скопируйте `.env.example` в `.env`.
2. Измените `SECRET_KEY`, `INITIAL_ADMIN_PASSWORD`, `POSTGRES_PASSWORD`.
3. При внешнем HTTPS укажите `BASE_URL` и `COOKIE_HTTPS_ONLY=true`.
4. Запустите:

```bash
docker compose up -d --build
```

Контейнеры:

- `toir` — FastAPI/PWA;
- `db` — PostgreSQL 16.

PostgreSQL хранится в Docker volume `toir_pgdata`, загруженные файлы — в каталоге `uploads`.

## Настройки внутри приложения

Администратор открывает:

```text
Настройки → Статусы заявок
Настройки → Приоритеты и SLA
Настройки → Категории работ
Настройки → Статусы оборудования
```

После сохранения изменения сразу применяются в списках, карточках и дашборде.

Системные коды статусов и приоритетов стабильны, чтобы не ломать бизнес-логику/API.
Их названия, цвета, активность, порядок и SLA можно менять. Новые значения через интерфейс
добавляются для категорий работ.

## Интеграция с 1С — опционально

По умолчанию:

```env
ONEC_ENABLED=false
ONEC_AUTO_PUSH=false
```

В этом режиме приложение не обращается к 1С, а входящие webhook 1С отключены.

Если клиенту нужна 1С, установите `ONEC_ENABLED=true` и заполните `ONEC_*` в `.env`.
`ONEC_AUTO_PUSH=true` включает автоматическую отправку изменений заявок; при `false` обмен
можно запускать вручную из раздела `Интеграции`.

Подготовленный ранее коннектор находится в:

```text
integrations/1c/
```

Он оставлен для совместимости с документом `ЗаявкаХозОтдела` и ранее подготовленными HTTP-сервисами.

## Переход с v0.2.2

Если уже есть `toir.db` от v0.2.2:

1. остановите старую версию;
2. сделайте копию `toir.db` и папки `uploads`;
3. положите БД рядом с v0.3;
4. запустите `run_windows.bat`.

Существующие заявки и оборудование сохраняются. Последние значения подсветок, ранее полученные
из 1С, становятся обычными локальными настройками системы и дальше редактируются в ТОиР.
Поля `one_c_id` сохранены исключительно для будущего коннектора.

## Телефон и удалённый доступ

Приложение — PWA. После публикации по HTTPS его можно установить на главный экран телефона.
Инструкция: `docs/PHONE_ACCESS.md`.

Для сервера без белого IP можно использовать Cloudflare Tunnel: наружу публикуется только ТОиР,
а база PostgreSQL остаётся внутри сервера.

## Безопасность перед показом/боем

- измените пароль администратора;
- задайте длинный случайный `SECRET_KEY`;
- при Docker измените `POSTGRES_PASSWORD`;
- для внешнего доступа используйте HTTPS;
- не открывайте PostgreSQL и порт 8000 напрямую в Интернет;
- включите `COOKIE_HTTPS_ONLY=true` после настройки HTTPS;
- включайте коннекторы только если они реально используются.

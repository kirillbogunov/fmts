# FMTS v0.7.5 — Advanced ITSM / SLA Calendars / CMDB Relations / Webhooks

## ITSM-контур

- У заявки появился тип: **Инцидент**, **Запрос на обслуживание**, **Проблема**, **Изменение**.
- Для диспетчера, руководителя и администратора добавлен раздел **ITSM / Изменения**.
- ITSM-дашборд показывает количество обращений по типам, просроченный SLA реакции/решения, открытые проблемы и календарь плановых изменений.
- Для типа `Изменение` можно задать плановое начало и окончание работ; окно отображается в карточке и календаре изменений.
- Связи между заявками дополнены вариантами `Проблема для`, `Вызвана проблемой`, `Изменение для`.

## SLA рабочего времени

- Добавлены рабочие SLA-календари: рабочие дни недели, начало/окончание рабочего дня, часовой пояс и список праздничных/нерабочих дат.
- В каталоге сервисов можно отдельно задать **SLA первой реакции** и **SLA решения** в рабочих минутах.
- Сроки по сервису считаются только внутри рабочего календаря. Например, срок может автоматически переноситься с пятницы на понедельник.
- В заявке хранится снимок выбранного SLA-календаря.
- Первая реакция фиксируется при первом рабочем действии сотрудника или его комментарии.
- Фоновая SLA-эскалация отдельно контролирует просрочку реакции и просрочку решения.

## CMDB

- Помимо родитель/дочерний узел добавлены произвольные связи оборудования.
- Типы связей: `Зависит от`, `Питает / обеспечивает`, `Сетевое соединение`, `Связано по размещению`, `Резерв для`, `Связано`.
- В паспорте оборудования отображаются входящие и исходящие зависимости и доступно управление ими по RBAC.

## Исходящие webhooks

- Добавлены настраиваемые endpoint'ы для внешних систем, n8n, CRM/BI и интеграционных шлюзов.
- События: `ticket.created`, `ticket.updated`, `ticket.comment`; поддерживается `*`.
- Очередь доставки хранится в БД и выполняется фоновым сервисом.
- До 5 повторных попыток с увеличивающейся задержкой.
- HMAC-SHA256 подпись в заголовке `X-FMTS-Signature`.
- Есть тестовая отправка, журнал доставок и ручной повтор неудачной доставки.

## Совместимость

Миграция additive: существующие данные v0.7.4 сохраняются. Старые заявки получают тип `incident`. Старый `default_sla_hours` сервисов автоматически переносится в `resolution_sla_minutes` при отсутствии нового значения.
